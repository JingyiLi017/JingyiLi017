# Agent 总控层设计（流程编排版）

## 目标
- 将“拆书 -> 写作结构 -> 正文生成 -> 体检 -> 回写 -> 风格进化”统一编排。
- 每一步可观察、可中止、可回滚。
- 自动执行前先过门禁，避免错误传播。

## 状态机
- `PLAN`：读取书籍上下文、资产快照、任务状态，确定下一步。
- `EXECUTE`：按顺序触发模块（拆书/结构/正文/体检/回写/进化）。
- `VERIFY`：检查阈值（连贯性、冲突密度、体检结果、反抄袭）。
- `COMMIT`：写入资产快照，记录审计日志。
- `LEARN`：更新模板权重、风格画像与策略参数。
- `HALT`：遇到高风险动作时停机等待人工确认。

## 编排顺序（默认）
1. 读取输入：创作简报 + 总纲 + 资产快照基线
2. 结构阶段：`1.2 -> 1.3 -> 1.4`
3. 生成阶段：`1.5`（单章或批量 1~5 章）
4. 体检阶段：一致性/冲突/设定/时间线/反抄袭
5. 回写阶段：事实层与台账更新
6. 学习阶段：风格进化 + 模板进化
7. 提交阶段：生成快照并落审计

## 门禁与回滚
- 体检评分低于阈值：阻断发布，只允许修复分支。
- 高风险策略变更：必须人工确认后应用。
- 每次自动应用都写 `agent_action_audit_log`。
- 回滚优先级：
  1) 资产快照回滚
  2) agent action 回滚
  3) 分卷版本回滚

## 观测指标（最小集）
- 结构完成率：1.2~1.5 每步状态与进度
- 质量门禁：体检通过率 / 平均分 / 失败原因
- 资产健康度：素材冗余率 / 模板命中率 / 快照频次
- 进化效果：风格版本增量、修复收益（delta）

## API 对接建议
- 总控诊断：`GET /v1/agent/diagnose`
- 总控提案：`POST /v1/agent/propose`
- 总控应用：`POST /v1/agent/apply`
- 总控回滚：`POST /v1/agent/rollback`
- 资产沉淀：`/v1/books/{book_id}/asset_snapshots*`

## 实施阶段
1. P1：总控只读（诊断+观测，不自动改）
2. P2：总控半自动（提案后人工确认）
3. P3：总控自动（门禁通过自动执行，失败自动回滚）
